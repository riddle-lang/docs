# 所有权与内存

Riddle 的内存模型围绕一个核心原则展开：值默认移动。

移动语义让资源归属更清楚，但 Riddle 不希望把所有内存管理负担都交给程序员。
因此它结合了移动语义、引用和自动逃逸提升：

- 普通值默认在作用域中移动；
- 引用没有逃逸时，值可以留在栈上；
- 引用逃逸当前作用域时，整个变量自动提升到运行时管理的堆区域；
- 提升只改变存储位置，不改变值的所有权、移动和析构语义。

这个模型的目标是：让常见代码写起来接近 Go 的轻松体验，同时保留移动语义带来的清晰归属。

默认运行时使用保守式非移动 GC。二进制项目也可以通过 Clue 提供自定义的非移动 GC、arena 或其他分配器；这只改变堆存储的实现，不改变移动检查、借用检查或逃逸分析。

## Drop 与确定性析构

实现 `std::ops::Drop` 可以在值的所有权结束时运行清理逻辑：

```riddle
struct FileHandle { raw: i32 }

impl Drop for FileHandle {
    fun drop(&mut self) {
        // 释放 raw 对应的外部资源
    }
}
```

局部变量按声明逆序析构，函数和闭包的按值参数按声明顺序析构。类型自己的 `Drop::drop` 先运行，随后结构体或元组字段按声明顺序、数组按索引顺序、枚举按当前 variant 继续析构。赋值会先析构旧值；移动出去的值不会在原位置再次析构。直接调用 `value.drop()` 会报告 `E0056`，提前析构应使用 `drop(value)`。

`match` 和 `for` 的非 `Copy` 模式绑定会取得对应值的所有权。未继续移动的绑定在 arm 或当前循环轮次结束时析构；`break`、`continue` 和 `return` 也会先清理正在离开的绑定。`for` 通过 `IntoIterator` / `Iterator` 运行，当前已经取出的元素归模式绑定所有，尚未取出的元素仍归迭代器所有，并在循环结束时随迭代器清理。实现了 `Drop` 的类型不能通过解构模式移出非 `Copy` 字段，这种代码会报告 `E0305`。

析构由所有权和词法作用域驱动，与对象位于栈还是 GC 堆无关。逃逸到 GC 堆的对象仍会在所有者结束时运行 `Drop`；GC 之后只负责回收内存，不充当 finalizer，也不会再次调用析构。发生 `panic` 时当前后端直接终止进程，不执行栈展开析构。
