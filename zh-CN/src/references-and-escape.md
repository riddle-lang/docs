# 引用与逃逸

引用让你在不移动值的情况下临时访问它。
Riddle 的引用模型和内存分配策略紧密相关：如果引用没有逃逸当前作用域，值可以留在栈上；如果引用逃逸，整个变量会自动提升到 GC 管理区域。

## 临时引用

临时引用最常见的用途是把值借给函数使用：

```riddle
struct Foo {
    x: i32,
    y: i32,
}

fun print_foo(foo: &Foo) {
    print(foo.x)
}

fun main() {
    let foo = Foo { x: 1, y: 1 };
    print_foo(&foo);
    print(foo)
}
```

`&foo` 没有逃出 `main` 的当前作用域。调用结束后，`foo` 仍然可以继续使用。

## 引用逃逸

如果引用离开了当前作用域，它就发生了逃逸。
常见的逃逸包括：

- 从函数返回引用；
- 把引用存进生命周期更长的数据结构；
- 让闭包或异步任务捕获引用；
- 把引用传给可能保存它的外部接口。

当逃逸发生时，Riddle 不要求你手动选择堆分配或写生命周期标注。
编译器会把整个变量提升到 GC 管理区域。

## 自动提升到 GC

看一个概念示例：

```riddle
fun make_ref() -> &Foo {
    let foo = Foo { x: 1, y: 1 };
    &foo
}
```

`foo` 的引用被返回了。它不能再只存在于 `make_ref` 的栈帧中。
因此 Riddle 会把整个 `foo` 提升到 GC 管理区域，让返回的引用保持有效。

这和 Go 的逃逸分析有相似之处：程序员通常不需要手动决定一个对象放在栈上还是堆上。
不同的是，Riddle 的普通值语义仍然以移动为核心。

## 提升后变成引用语义

一旦变量被提升到 GC，它会自动变成引用语义。
这意味着多个地方可以持有指向同一个 GC 对象的引用，而对象的存活由 GC 管理。

```riddle
fun main() {
    let foo = Foo { x: 1, y: 1 };
    let a = &foo;
    let b = a;
    print(b.x)
}
```

如果 `a` 或 `b` 的使用方式导致引用逃逸，`foo` 会被提升。
提升之后，围绕这个对象的访问更接近引用语义，而不是普通栈上值的移动语义。

## 为什么这样设计

Rust 要求程序员显式面对借用和生命周期，这能换来非常强的静态保证，但学习成本很高。
Go 让编译器做逃逸分析，程序员写起来轻松，但值的归属感没有那么强。

Riddle 尝试结合两边的优点：

- 普通值用移动语义保持清晰归属；
- 临时引用保持轻量；
- 逃逸时自动提升，不要求手写生命周期；
- 提升后交给 GC 管理，避免悬垂引用。

## 小结

- 引用用于临时访问值；
- 引用不逃逸时，值可以留在栈上；
- 引用逃逸时，整个变量自动提升到 GC；
- 提升后对象变成引用语义；
- 这个模型借鉴 Go 的逃逸分析，同时保留 Riddle 的移动语义。
