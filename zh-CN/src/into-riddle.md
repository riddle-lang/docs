# 进入 Riddle 编程世界

Riddle 最初是 Zi2ven 的个人项目，后来有了一个较小的用户群体（以及一个疯狂写代码的 Zi2ven）并继续发展。
实际上你看到的版本可能已经是 Riddle 的第几十个重构版本，因为我们始终不满意效果并最终修改到目前的样子。

遗憾的是迄今为止 Riddle 依旧不能进入生产，这是因为我们在设计之初设想了一个目标就是能够在裸机环境下运行，
因此我们抛弃了非常多的内存管理方案。目前我们探索的方向是类似 Nim 和 Koka 的改进版 Arc，希望在保证安全性的同时减少对复杂运行时的依赖。

## 为何又来一门新语言？

简而言之，我们缺少一个**学习难度平缓并且内存安全且尽量减少依赖**的工程语言。
我们似乎找不到完全符合这个目标的语言，因此决定自己实现一门语言。

Riddle 的目标不是替代所有语言，也不是证明现有语言都不好。它更像是一次工程语言设计实验：

- 尽量让语法保持直接，不把简单问题包装成复杂概念；
- 尽量让代码结构天然便于拆分和重构；
- 尽量减少运行时假设，让语言更容易进入受限环境；
- 在安全性和性能之间寻找更容易理解的平衡点。

### 便于重构

Riddle 在设计之初就考虑到了重构。实际上这门语言本身的创造者也饱受重构之苦。
经常一不留神就会写出高耦合度的代码，后续想要重构就需要付出大量的代价去先模块化才能分步重构。
使用 Riddle 可以方便的重构各个部分，因为 Riddle 使用了部分的函数式编程（Functional Programming）范式来保证每个部分都是可替换的。

尽管这样不可能自动消除所有复杂度，但是至少能降低面对陌生代码时无从下手的概率。

### 效率

下面从三个角度来谈谈 Riddle 的效率：学习、运行、开发。

#### 学习效率

实际上 Riddle 拥有非常**简单**的语法和语义，并且简化了生命周期管理方面的困难。

我们尽量减少可能导致多种语义的语法，也在尝试减少设计完善系统的复杂度。至于效果如何，还需要更多真实代码来检验。

#### 运行效率

得益于各种优化，深入到底层的优化潜力、优质的标准库和第三方库实现，
Riddle 的性能非常优秀，虽然可能比不上 Rust，C++ 在极端情况下的速度，但我们认为依旧可以够用。

当然的，如果正确使用 Riddle，性能可能会比 C/C++ 写的老工具还要好。

#### 开发效率

Riddle 的语法刻意保持接近主流工程语言。如果你写过 Rust、C、JavaScript、Go、Kotlin 或类似语言，应该能很快看懂 Riddle 的基本结构。

例如，一个函数声明大致长这样：

```riddle
fun add(a: i32, b: i32) -> i32 {
    a + b
}
```

上面的函数体最后一行没有分号，它会被当作块的尾表达式。这个规则和 Rust 类似，也能减少临时变量和多余的 `return`。

## 本书如何阅读

如果你只是想快速体验，可以先阅读“开始使用 Riddle”一章，完成安装并写下第一段 Riddle 代码。
如果你想系统学习这门语言，可以按顺序阅读“Riddle 基础”“数据与抽象”和“所有权与内存”。
